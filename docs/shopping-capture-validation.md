# Actual shopping Overview projection

Captured 5 November 2026 for `running shoes for flat feet`, US/English, in an ordinary in-app browser. This is supplied rendered evidence, not proof that the HTTP SDK can retrieve the same response. The parent capture contains actual main/source columns; the test fixture reconstructs the wrapper and a separately observed AI Overview heading. [Fixture provenance](../tests/fixtures/google-search/aio-provenance.json).

The parser extracts **11 product-viewer links, 7 citation sources and 10 citation entries**. Product links include title, one-based position, native Google product ID and Google viewer URL. These extra `productLinks` are separate from citations; no merchant URL, price, availability or Cloro product-result token is invented. The native viewer URL's product ID must match the observed `data-cid` attribute. A YouTube citation in this capture is not a video card.

The real capture exposed two formatting defects: Google's accessibility helper label entered product names, and nested divs broke Markdown emphasis/link delimiters. The parser now removes the exact helper only inside recognized product-viewer anchors and normalizes their labels. The Markdown walker keeps nested inline wrappers within emphasis/link context. Regression checks include the real product title/variant formatting, source and product separation, and explicit synthetic ownership/URL boundaries.

“Related results” buttons are citation controls. This capture does not establish Cloro-style `relatedLinks` ownership, so it does not justify populating that array. There are no answer video, iframe, table or preformatted-code elements in its main column. Its ten main-column images belong to citation controls, while the source column contains twenty image nodes including publisher thumbnails/icons. All image src payloads are removed from the sanitized regression fixture; it establishes no image-rendering or asset-completeness claim.

The fixture preserves public product identities while discarding request tracking, account headers, scripts, CSS and image bytes. Targeted parser/monitor/Markdown/product tests pass (151 tests), with type checking. These are local implementation checks, not an upstream availability or universal-layout benchmark.
